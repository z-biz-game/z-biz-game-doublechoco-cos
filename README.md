# 双巧克力 · DOUBLE CHOCO / ダブルチョコ（零猜测区界推理）

一盘棋面上有两种底色的格子，你要做的只有一件事：**在格子之间的虚线上画区界**。
每一块区域都由"一片白格 + 一片同形的灰格"配成，格上的数字说的是**它自己那种颜色**在本块里有几格。
画错一条，判据当场点名是哪一句条款被违反；画对全部，盘面通关。

这个仓对外只说三句话，每一句都有可复跑的命令在背后：

1. **每一局都唯一可解**——不是"我们的求解器只找到一条"，是这块盘的合法分块在**无上限规则**下被完整枚举过，
   然后逐个数过（`js/engine/blocks.js:92`、`js/engine/count.js:11`）。
2. **每一步都推得出来**——界面上提示落下的每一子都由一条**具名规则**点名，说不出证人的那一步界面宁可不落子
   （`js/engine/pencil.js:25-37`、`js/ui/game.js:239-289`）。
3. **难度是量出来的**——菜单上的轮次、数字个数、区界条数都来自 `js/engine/tiers.js:47-65` 的 golden 数组，
   而那份数组每次 CI 都由 `tools/balance.mjs` 的 B1/B3 逐值复跑（红线绿才允许留着）。

另有两处**披露**（不是缺陷清单，是承诺的边界，DESIGN.md 里各有一节）：
"area 必须连通"（V7）是我们对出版方原句做的字面裁定，不是出版方的裁决；
出题器有确定量的枚举预算，撞预算时它**换一张底纹**而不是放宽判据——所以承诺是"这一盘在无上限规则下唯一"，
不是"每一种底纹都算得起"。

## 玩法

题面给两样东西：**底纹**（哪半盘是灰格）与**数字**。玩家只画界，不改底纹、不填数字。

| 条款 | 原句（`js/engine/rules.js:59-70`） | 说的是什么 |
| --- | --- | --- |
| V1a | Divide the grid into blocks | 每一格恰好属于一块，不许有无处可去的格 |
| V1b | 同上 | 一格不许同时属于两块 |
| V2 | 同上 | 一块之内的格子必须连成一片 |
| V3 | exactly half of cells are painted gray | 每块两半等量：灰格数 == 白格数 |
| V4 | a pair of areas … same form | 两块同色半区必须**同形**（可旋转、可镜像） |
| V5 | A number indicates the number of cells of that color | 数字数的是**该格自身颜色**在本块里的格数，且等于块大小的一半 |
| V6 | the cells contain the same number | 一块之内出现的数字必须彼此相同 |
| V7 | one **area** of white cells and one area of gray cells | 每块的白半区、灰半区各自都必须是一片（连通） |

盘边与相邻格之间的每一条虚线都是一个可落子的**段**：段数 = `R·(C−1) + (R−1)·C`，
4×4 是 24 段、6×6 是 60 段、8×8 是 112 段（`js/ui/game.js:28-43`）。
区域是"跨不过已画之界"的连通分量，所以**画一条界不会把整盘断成两半**——这一点在浏览器闸里被直接断言
（`tools/scenarios.js:421`），不是靠肉眼看着像。

通关判据只有三件：违反为 0、与唯一解不一致的段为 0、已画的界不为零（`js/ui/game.js:304-314`）。
"还差几条界"是**读数**不是判据，它故意不在 `winFacts()` 的键里，闸也就此断了一句：
`胜负不读进度`（`tools/scenarios.js:538`）。

## 四档菜单，以及为什么没有 10×10

档位由实测排序，不由边长排序（`tools/balance.mjs:82` 的 B2 断言轮次严格升、数字占比严格降）：

| 档 | 盘幅 | 题面数字 | 要画的界 | 推理轮次（中位 / p95） | 工作量中位 |
| --- | --- | --- | --- | --- | --- |
| 初 sho | 4×4 | 16（全盘印满） | 10 | 2 / 4 | 204 |
| 中 chuu | 6×6 | 13 | 28 | 4 / 6 | 1,254 |
| 高 gao | 6×6 | 4 | 29 | 6 / 10 | 10,260 |
| 极 kyoku | 8×8 | 5 | 59 | 9 / 14 | 1,068,386 |

数字来自 `js/engine/tiers.js:47-65` 的 gold 数组（八号 seed 的实测值，排序后钉住），
不是形容词。菜单外那一行（`js/engine/tiers.js:80-95`）说的是 5×5 这类**奇数格盘**与 10×10：
前者是规则本身的结论（一块 = 白 area + 同形灰 area ⇒ 每块偶数格 ⇒ 全盘偶数格，`tools/engine-test.mjs:289-291` 直接断言它被拒），
后者是成本：40 万次工作量预算下多数底纹算不起、12 块底纹换完仍钉不死的也不少，
所以"每一号 seed 都有一盘可推、而且等得起"这句承诺给不出——`tools/balance.mjs:130` 的 B5 每次都真的去抽 8 盘并当场打印出货率。

## 操作

| 动作 | 指针 | 键盘 |
| --- | --- | --- |
| 选中一格（移光标） | 点格子中间 | `←↑→↓` |
| 在光标与某邻居之间画界 / 再按一次擦掉 | 点盘上那条虚线；按住拖过去可连着画一条；或用四只方向键 | `Shift` + 方向键 |
| 提示（引擎点名的那一条界） | 「提示」 | `H` |
| 撤销 | 「撤销」 | `Z` 或退格 |

四只落子键每只都带着它当场那条段的**段名**（`aria-label`），所以"这个键在画哪一条界"是页面上读得到的，
不是只画了箭头；走到盘边那一面没有相邻格，那一只键就被标成不可用、并且不挂着按下态
（`js/main.js:207-234`，浏览器闸里 `盘边那只 ↑ 键被标成不可用` / `不可用的那只键没有残留按下态` 两行钉着）。

## 验证：四条命令，以及它们各自说什么

```bash
npm test                      # engine-test + ui-smoke 两条链，纯 node，无浏览器；条数由命令自己打印
node tools/balance.mjs        # B1–B6 的红线：出货、阶梯方向、golden 逐值、完整池、成本上限、预算复跑
bash tools/verify.sh          # 真浏览器闸：headless Chrome + CDP，两种 URL 形态各跑一遍全部腿
GATE_SELFTEST=1 bash tools/verify.sh   # 阴性自证：种一条注定错的期望，必须红并且 rc≠0
```

前三条命令的绿都在 CI 里（`.github/workflows/ci.yml`）。第四条不在 CI 的主路径上，
但它回答的是"这条闸能不能红"——CI 里紧跟着一步 `Gate proves it can fail` 就是它。
`bash tools/verify.sh` 把默认那串腿（`tools/verify.sh:78`）× 2 种 URL 形态各跑一遍：哪条腿跑哪些场景写在
`tools/verify.sh:163-219`，场景名注册表在 `tools/scenarios.js:947`；`GATE_SELFTEST=1` 时**每一份报告都必须点名吃下种下的错**，
应有份数由 `tools/verify.sh:231-240` 的对数表按腿的形状算出来（`core|play|win` 各 2 份、`mouse|touch|keys` 各 1 份、`save` 5 份），
少一份就红，写的是"有腿没跑，或对数表漂了"。

浏览器闸读的是 DOM 文本、几何、画布像素和真实输入事件，**不读内部标志位**：
`.status` 字符串说的是代码想要什么，client rect 和一个像素说的是玩家拿到了什么。
四条腿的名字就是四条承诺：`play`（画得动、撤得回、待画是读数）、`hint`（提示每一步都点名具名规则）、
`win`（判据与进度分开、通关只认三件事）、`save`/`resume`（存档不带解，续局当场重证）。
真事件的三条腿（`mouse` / `touch` / `keys`）用 CDP `Input.dispatch*` 派发，
先断命中盒再谈"点得到"，触屏腿自己读回覆写证人（`innerWidth=390 / dpr=3`）而不是另起进程设好覆写再来量。

## 不承诺

- **不承诺**任意尺寸可玩。菜单只有 4×4 / 6×6 / 8×8；奇数格数是规则结论，10×10 是成本结论（见上）。
- **不承诺**"所有底纹都算得起"。撞预算的底纹被换掉，被换掉的那份工作量照样记账（`tools/balance.mjs:105` 的 B3b 反过来钉：
  出货那一盘的枚举必须**没撞预算**，否则"无上限规则下唯一"这句话不可证）。
- **不承诺**界面提示是"唯一可能的下一步"。它给的是当前盘上某一条具名规则**当场能钉死**的一步，
  规则名与它点名的段一起印在屏幕上（`js/ui/game.js:258-266`）。
- **不裁决**出版方没有裁决的事。V7 的连通读法是我们写的裁定，宽松读法在官方 4×4 例题上给出同一唯一解——
  这一句是断言不是忏悔：`tools/engine-test.mjs:139` 第 3 段要求存在"只违反 V7"的见证盘。

## 上线的到底是哪一批文件

这个仓没有打包器：站点=一次文件拷贝。以前「拷哪些」写在 `pages.yml` 的 `run:` 里（手抄的几行
`cp`）。本地 `index.html` 直读仓库根，永远自洽；线上却按那份清单拷，于是页面后来引用的
`manifest.webmanifest`、`sw.js`、`icons/*` 可能一个都没上去——线上 404，而仓里的引擎测试与
真浏览器闸全绿，因为它们跑的都是仓库根，没有任何一步在「按清单拷」的那个环境下加载过页面。

现在清单只有一份，住在 `tools/assemble-site.sh`：CI 调它拷 `_site`，本地闸调它拷临时目录，
然后**对拷出来的产物**提要求（`tools/deploy-set.mjs`）：

- **W 清单与页面同源**：`pages.yml` 里必须真有 `run: bash tools/assemble-site.sh <dir>` 这一行，
  `ci.yml` 里必须真有 `run: node tools/deploy-set.mjs`。认的是调用那一行，不是文件里出现过这个
  路径——注释里本来就会写它，只 grep 字符串会被一句散文喂绿。
- **R 引用可达**：引用不靠手打名单。从 `index.html` 的 `href/src` 出发，凡解析出来是 `.js`/`.css`
  的就把那一站也扫一遍（CSS 的 `url()`、JS 去掉注释后的 `'./…'` 字面量、`new URL(x, base)` 的两种
  基、`navigator.serviceWorker.register`、`scope`），`manifest` 的 icons/screenshots/shortcuts 各自
  的 `src` 也算引用。取径上读不到的那一站本身就是红（读不到＝这一站根本没扫）。每条引用都必须在
  产物里且非 0 字节；绝对路径单列一条红，因为 Pages 挂在 `/<repo>/` 前缀下会跳出去。
- **P 位图不许说谎**：`manifest` 声明的 `sizes` 必须等于 PNG IHDR 的真实宽高——文件图标读文件头，
  内联成 base64 的图标先解码再读同一段。后一条不是可选项：图标可能住在清单里而不是盘上的 `.png`
  （有的仓另有一条"零二进制文件"的承诺，那条只约束"有没有 .png 这个文件"）；如果 P 段只筛文件名，
  声明写 512 而真图 192 就一路放行。
- **钉住两个数**：R 段实际检查的路径条数（`42`）与这一次跑的断言条数（`60`），两个数
  都钉在 `tools/deploy-set.mjs` 顶部的那对常量里。没改页面却掉了，说明解析断了；删掉一张图标会同时
  少一条 R10 与那张的 P1/P2，所以两个数一起钉，断言条数能漂就是闸在缩水的信号。这一节故意只写数值、
  不写那对常量的名字，也不写别仓文档闸的编号：有的仓的文档闸会拿"文档里出现过的同名标识号"回数它
  自己的条数，还有的会把文档里点到的每个组编号逐个核对"这一轮真的发过"——两道闸共用一个名字，
  或者在本仓的文档里出现一个本仓没有的组编号，打红的都是不相干的那一边。

`tools/deploy-set-selftest.mjs` 是这两颗钉的阳性证明：它把仓库复制到临时目录，照着每一类断言
各下一刀（X1 清单不收位图目录 / X2 模块边改名 / X3 CSS 写绝对路径 / X4 `start_url` 绝对 /
X5 删光 >=512 图标 / X6 少一个必填字段 / X7 声明尺寸与真图不符 / X8 workflow 不调脚本 /
X9 CI 不跑闸 / X10 是阴性对照——往入口 JS 追加一行只写在注释里的假路径，闸必须仍然绿、条数仍然
`42`、断言仍然 `60`；X11 og:image 退回相对路径 / X12 og:image 的前缀指向别的 slug /
X13 内联位图谎报尺寸——只在有靶子时下：X11/X12 要页面上那句 og:image，X13 要清单里真有一段 base64
图标，没有就打印 SKIP；反过来 X1 没有位图目录可砍时改砍 css，P 段一位都不核时台架直接报靶子不够），
要求每一刀都让闸**点名**变红。靶子从 `DEPLOY_SET_DUMP=1`
的出处表现挑（取径真的会读的那支 JS / 那一张 CSS，不写死某一个仓的入口名），所以页面改了、仓与仓
不同，台架跟着走。

`node tools/deploy-set.mjs` 与 `node tools/deploy-set-selftest.mjs` 就是 CI 跑的那两条命令本身
（package.json 里的 `deploy-set` / `deploy-set:selftest` 只是同一支脚本的 npm 入口）；把它们接进本仓
那条浏览器 one-shot（`tools/verify.sh`）还欠着——那道脚本的腿名单与条数钉是每个仓自己的形状。
